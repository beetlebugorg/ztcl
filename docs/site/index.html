Fast, sandboxed Tcl in Zig.

ztcl runs Tcl 8.6 scripts on a bytecode VM, with exact step and memory limits. A script reaches the host only through the capabilities that your program gives it.

Get started GitHub

An optional JIT for x86-64 Linux. A WebAssembly build. No dependency outside the Zig standard library.

proc sum {n} {
    set total 0
    for {set i 0} {$i < $n} {incr i} {
        incr total $i
    }
    return $total
}

Performance

Measured against tclsh, with the JIT off and on.

The interpreter compiles each script to bytecode. The optional JIT compiles hot procs to x86-64 machine code. Tier 2 keeps integer and double loop variables in registers.

The sandbox

A script gets only what you grant.

The default interpreter has no command that reaches the host. puts writes to a callback of your program. Run untrusted scripts with a hard limit on steps and memory.

Capabilities, off by default

Files, sockets, exec, clock, and the event loop are absent until the embedder turns each one on.

  • file and channels stay inside one root folder.
  • socket follows a network policy: loopback, an allowlist, or any.
  • A child interp never has more capabilities than its parent.

Exact limits

Each interpreter has a step limit and a memory limit. The limits are exact, also with the JIT on.

  • Step limit, memory limit, nesting depth, and native stack.
  • At a limit, the script stops with an error that catch and try cannot catch.
  • A script must not crash the host.

Deterministic

With no capability on, the output of a script depends only on the script, the seed, and the inputs of the embedder.

  • No clock and no timers by default.
  • The same script gives the same result on each run.

exec is not sandboxed. It is a separate capability. A process from exec runs outside the root folder and outside each limit, with the full power of the user.

Modern features

The Tcl you know, on a new engine.

ztcl follows the 12 rules of Tcl and the core commands of Tcl 8.6: lists, strings, dicts, arrays, expr, regexp, namespaces, try, apply, lmap, and TclOO. Coroutines work on x86-64 Linux.

Interpreter

Bytecode VM

Scripts and proc bodies compile to bytecode. Each command and each loop pass uses one step of the step limit.

Memory

Garbage collector

A conservative collector frees the values that a script no longer reaches. With --gc off, the point where the memory limit stops a script is exact.

Numeric scripts

SIMD point procs

A point proc compiles one body to a vector program over blocks of 1024 points. On the fuzzy skin benchmark, it uses about 15 ns for each point against about 230 ns on the normal path.

Experimental

JIT, tier 1

On x86-64 Linux, --jit compiles proc bodies to machine code. Integer arithmetic, compares, incr, and some list paths run inline. It is off by default.

Experimental

JIT, tier 2

--jit-tier2 compiles a hot loop a second time, with integer and double variables in registers. A failed check exits to tier 1 at the same instruction.

Portable

WebAssembly

zig build wasm builds ztcl.wasm. The WebAssembly build has the same sandbox and runs on the interpreter.

A JIT with safety rules

The JIT has the same sandbox and the same limits as the interpreter.

  • W^X code memory. Code memory is never writable and executable at once.
  • A verifier. It checks each bytecode before the JIT compiles it.
  • No script values in code. No value from a script goes into the machine code.
  • Differential fuzzing. Fuzzers compare the output of the JIT with the interpreter.
  • The same results. A JIT run gives the same results and step counts as the interpreter on the whole Tcl test suite.

Embedding in Zig

Add a scripting language in a few lines.

ztcl is a Zig package with no other dependency. Set the limits, register your own commands, and evaluate scripts.

  • register(name, fn) adds a native command.
  • output is the callback of puts.
  • enableJit(.{}) turns on the JIT where the build has one.

const dep = b.dependency("ztcl", .{
    .target = target,
    .optimize = optimize,
});
exe.root_module.addImport("ztcl", dep.module("ztcl"));
main.zig
const ztcl = @import("ztcl");

var it: ztcl.Interp = undefined;
try it.init(gpa);
defer it.deinit();
it.step_limit = 1_000_000;
it.mem_limit = 64 << 20;
const v = try it.eval("expr {6 * 7}");

Status

Experimental, and measured in the open.

ztcl aims to become a complete drop-in replacement for Tcl. It is not one yet. APIs and behavior can change in any release.

  • WorksTcl 8.6.16 test suite: 37 383 of 46 494 tests pass in all 152 files (80.4 %). Compatibility has the result for each file.
  • WorksThe interpreter, the garbage collector, point procs, and the WebAssembly build.
  • ExperimentalThe JIT on x86-64 Linux. It is off by default. Turn it on with --jit and --jit-tier2.
  • In progressThe JIT on arm64 macOS.
  • In progressThe speed of TclOO method calls. bf_oo uses 1.33 times the instructions of tclsh 8.6.16.
  • Open bugsTwo bugs of the limits: a memory limit bug (#5) and a step limit cost bug (#6).
  • NoteThe code and the docs were written largely with AI coding agents, under human direction. Review the code before you depend on it.
