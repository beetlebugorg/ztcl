Modern Tcl for the AI era. Sandboxed, compiled, and built for agents.

The fastest, most complete alternative Tcl, written in Zig. It runs Tcl 9.1 and 8.6 scripts with a JIT. Each script gets an exact compute limit, a memory cap, and no host access until you allow it.

Designed with AI in mind

Run code that you did not write.

An agent writes a script, and your program runs it with an exact work limit, a memory cap, and only the host access that you name. The shell above runs this way.

Exact limits

A script stops at the same compute unit on each machine and JIT tier, with an error that catch cannot catch. Limits.

Host access by capability

A new interpreter has no files, sockets, processes, clock, or environment. You allow each one with a policy. Capabilities.

Agents in the language

ztcl::agent runs an LLM agent loop in an isolated thread, with Tcl commands as tools. Sandboxed agents.

Tools for agents

Speed

Measured on real tasks, against Tcl, Python, Go, and Zig.

The same 14 tasks in each language, with standard libraries and equal output. Times are wall-clock milliseconds. bench/compare runs them all.

  • Against tclsh 8.6.16: 1.8 times as fast at the median, up to 12.8 times (CSV). Slower on base64 end to end, because of a slow file read (#696).
  • Against Python 3.14: faster on 6 of 11, such as JSON (2 times) and the HTTP server (3.7 times). Slower on base64, CSV, regex, and word frequency.
  • Against Go and Zig: Go is faster on 7 of 11, and ztcl on JSON, formatting, templates, and HTTP. Zig is faster on all 11.
  • The JIT halves recursive fib. Real tasks spend their time in built-in commands, so the JIT changes them little.
  • Micro benchmark: an integer loop in a proc is about 50 times as fast as in tclsh. That case is narrow.

Intel i7-6700K, Linux, 2026-11-27, 15 rounds, on a shared host: pale bars have a wide spread. Performance has all results and the method.

Isolation and VMs

A thread, a process, or a microVM for each job.

Real threads, each with its own interpreter, heap, and limits. -isolation process puts a thread in an OS sandbox, and -isolation vm in a Linux microVM with no QEMU. On KVM, a guest thread starts in 9.6 ms, and a snapshot restores in 0.42 ms. Isolated threads and Linux guests.

Batteries

TLS, HTTP/2, JSON, and an agent loop, with no C library.

TLS 1.3 of our own

ztcl::tls socket is a TLS 1.3 client in Zig, checked with RFC 8448, the Wycheproof sets, and openssl. AES-GCM runs at 3,485 MB/s, and OpenSSL at 3,538 MB/s on the same machine. TLS 1.3.

An HTTP/2 server engine

It passes h2spec 2.6.0, 146 of 146. With h2load on one thread, it gives 317,872 requests/s, and nghttpd 1.71.0 gives 140,625. The Tcl command for it is in #27.

JSON from simdjson

ztcl::json parses twitter.json to Tcl dicts at 1,180 MB/s, faster than Python orjson and Node.js. ztcl::json get reads one value with no full parse. ztcl::json.

Sandboxed agents

ztcl::agent runs an LLM agent loop in an isolated thread with only the data and the tools that you give it. Sandboxed agents.

Web and WebAssembly

The same interpreter in the browser, and a wasm engine in ztcl.

npm install @beetlebug/ztcl: a 508 KB module with the same limits, and dom and web:: for the page. ztcl::wasm runs WebAssembly with its own JIT and passes the full core spec suite.

Tools and debugging

Build, strip, embed, and debug.

One binary for your program

ztcl build puts the runtime and your scripts in one static binary for Linux, macOS, or Windows, from any host. --strip keeps only the commands that the scripts use: hello world is 1,236,273 bytes. Build a program.

Debug with no puts

ztcl debug explains an error, records and replays a run, is a DAP debugger for your editor, and serves MCP tools to an agent. Probes record values in a running script. Debugging.

Embed in Zig or C

zig fetch adds ztcl to a Zig program with no C toolchain. libztcl builds C programs and Tcl extensions against ztcl as libtcl8.6. Embedding.

Compatibility

Tcl 9.1 by default, Tcl 8.6 on request.

More than 38,100 Tcl 8.6.16 tests and 11,165 Tcl 9.1 core tests pass. The JIT gives the same output as the interpreter. With libztcl, the unchanged tclsh8.6 runs on ztcl. Tcl 9.1 and Tcl 8.6.
