# Task 09: the base64 codec

## Goal

`binary encode base64` and `binary decode base64` use at most the instruction counts of `tclsh` 8.6.16.

## Files

- `src/more.zig` (or the file that has `binary encode`), `src/tests.zig`.

## The work

- Measure first. `perf record` on `tests/mem/b64enc.tcl` and `b64dec.tcl` shows where the 6.9 M and 16.1 M instructions for one call go. Report the profile in the PR body.
- Encode: compute the output size, allocate one time with `allocBytes`, and write 4 bytes for each 3 bytes of input from a 64-byte table. Handle `-maxlen` and `-wrapchar` outside the main loop when they are absent.
- Decode: one pass with a 256-byte table. Skip white space. Keep the `-strict` rules and the error messages of `tclsh`.
- A string value is UTF-8 and `binary` sees a character below 256 as one byte. Keep that rule: an input that is all ASCII needs no convert step. Check it one time with a word-wide scan.

## Acceptance

```sh
CAP zig build test
CAP tools/suite.sh binary.test             # pass 602 or more
CAP perf stat -e instructions:u zig-out/bin/ztcl tests/mem/b64enc.tcl 200
CAP perf stat -e instructions:u zig-out/bin/ztcl tests/mem/b64dec.tcl 200
CAP tools/kostya.sh                        # all three programs
```

Gates:

- `b64enc.tcl` with 200 passes: at most 853 M instructions. `b64dec.tcl` with 200 passes: at most 944 M. Both are the counts of `tclsh` 8.6.16 on 2026-11-23.
- `base64/test.tcl`: the ratio of instruction counts against `tclsh` is at most 1.0, and the output is equal.
- `bf.tcl bench.b` and `bf_oo.tcl bench.b`: the ratio is at most the number that the user set after task 06 (provisional: 0.5).

## Must not change

The results of `binary`. The pass counts.
