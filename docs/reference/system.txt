# The command reference: the system. The format is in
# docs/reference/README.md.

== info
syn: info subcommand ?arg ...?
does: Facts about the interpreter: its commands, procs, variables, and the call stack.
sub: info commands ?PATTERN? | The names of the commands.
sub: info procs ?PATTERN? | The names of the procs.
sub: info exists VAR | 1 when the variable has a value.
sub: info vars ?PATTERN? | The visible variables.
sub: info globals ?PATTERN? | The variables of the top level.
sub: info locals ?PATTERN? | The local variables of the proc.
sub: info args PROC | The argument names of a proc.
sub: info body PROC | The body of a proc.
sub: info default PROC ARG VAR | 1 when the argument has a default, which goes in VAR.
sub: info level ?N? | The depth of the call stack, or the command at level N.
sub: info complete SCRIPT | 1 when the script has no open brace, bracket, or quote.
sub: info script ?NAME? | The file of the script that `source` runs.
sub: info functions ?PATTERN? | The names of the math functions.
sub: info cmdcount | The count of commands that ran.
sub: info patchlevel | The version of Tcl that ztcl follows: 8.6.16.
sub: info tclversion | 8.6.
sub: info library | The folder of the Tcl library: empty in ztcl.
sub: info loaded | The loaded binary packages.
sub: info nameofexecutable | The path of the program.
sub: info sharedlibextension | The extension of a shared library.
sub: info hostname | The name of the host.
sub: info errorstack ?INTERP? | The `-errorstack` of the last error: INNER and the failed command, then CALL and the words of each proc that the error left, and UP and a count of levels for a catch in the frame of `uplevel`.
sub: info coroutine | The full name of the running coroutine, or an empty string.
sub: info class SUBCOMMAND CLASS ?arg ...? | Facts about a TclOO class, as `info class` of Tcl 8.6.
sub: info object SUBCOMMAND OBJECT ?arg ...? | Facts about a TclOO object, as `info object` of Tcl 8.6.
diff: `info frame` is not in ztcl in this version: it gives the error "not supported by ztcl". The first word pair of `info errorstack` is INNER and the text of the failed command, where Tcl has the words of its bytecode instruction.
ex: proc f {a {b 2}} {}; info args f => a b
ex: info complete "set x \{" => 0
ex: info patchlevel => 8.6.16

== clock
syn: clock subcommand ?arg ...?
does: The time. `clock seconds` gives the seconds since 1970-01-01 UTC. The time and the zone data come from the host.
cap: clock
flags: --allow clock
sub: clock seconds | The seconds since the epoch.
sub: clock milliseconds | The milliseconds since the epoch.
sub: clock microseconds | The microseconds since the epoch.
sub: clock clicks ?-milliseconds|-microseconds? | A counter for time spans.
sub: clock format SECONDS ?-format FMT? ?-gmt BOOL? ?-timezone ZONE? ?-locale L? | The time as text. `%Y-%m-%d %H:%M:%S` and the other fields of `strftime`.
sub: clock scan TEXT ?-format FMT? ?-gmt BOOL? ?-timezone ZONE? ?-base SECONDS? | The seconds of a time in text.
sub: clock add SECONDS ?COUNT UNIT ...? ?-gmt BOOL? ?-timezone ZONE? | The seconds after adding days, months, and other units.
ex: clock format 0 -format %Y-%m-%d -gmt 1 => 1970-01-01
ex: clock scan 1970-01-02 -format %Y-%m-%d -gmt 1 => 86400

== http
syn: http::geturl url ?-option value ...?
does: The http package 2.9.8 of the Tcl library, with `package require http`: an HTTP/1.1 client on the sockets of ztcl. `http::geturl` sends a GET, a POST with `-query` or `-querychannel`, or a HEAD with `-validate 1`, and gives a token, the name of an array with the status, the headers, and the body of the reply. With `-command` the request runs in the event loop and the command gets the token at the end. `http::config` sets the proxy, the user agent, and the other defaults, `http::formatQuery` encodes a query, and `http::status`, `http::ncode`, `http::meta`, `http::data`, and `http::cleanup` read and free a token. A request with `-keepalive 1` uses one persistent socket for each host and port. `https` URLs use the TLS channels of `ztcl::tls`. `package require http 1.0` gives the old commands `http_get`, `http_config`, and the others.
cap: package
flags: --allow package,channels
names: http::config http::geturl http::formatQuery http::quoteString http::reset http::wait http::status http::size http::code http::ncode http::meta http::data http::error http::cleanup http::register http::registerError http::unregister
ex: package require http => 2.9.8
ex: http::formatQuery name "a b" x & => name=a%20b&x=%26
diff: The requests on one persistent socket go one after the other, so `-pipeline` does not change the order on the socket. The codings gzip, deflate, and compress need the `zlib` command, so the default Accept-Encoding is identity.

== tcl::OptProc
syn: tcl::OptProc name description body
does: The opt package 0.4.9 of the Tcl library, with `package require opt`: a proc whose words are checked against a description of flags and parameters. Each item of the description is a flag (`-name`) or a parameter (`name`, or `?name?` when it is optional), with a type (`-int`, `-float`, `-boolean`, `-string`, `-list`, `-choice LIST`, `-any`), a default value, and a help text. A flag can be a prefix of its name in any case. The body sees a variable for each item. `-help` gives a table of the items, and a missing, bad, or extra word gives an error with that table.
cap: package
flags: --allow package
names: tcl::OptKeyRegister tcl::OptKeyDelete tcl::OptKeyParse tcl::OptKeyError tcl::OptParse tcl::OptProcArgGiven tcl::OptCheckType tcl::Lempty tcl::Lget tcl::Lvarset tcl::Lvarset1 tcl::Lvarincr tcl::Lvarpop tcl::Lassign tcl::SetMax tcl::SetMin
ex: package require opt => 0.4.9
ex: tcl::OptProc greet {{name -string "who"} {-loud}} {list $name $loud}; greet Ann -l => Ann 1

== platform::generic
syn: platform::generic
syn: platform::identify
syn: platform::patterns identifier
does: The platform package 1.0.19 of the Tcl library, with `package require platform`: the system and the CPU as one identifier OS-CPU, such as `linux-x86_64` or `macosx-arm`, from `tcl_platform`. `identify` gives the same identifier as `generic`. `patterns` gives the identifiers that a package built for an identifier can run on, ending with `tcl`.
cap: package
flags: --allow package
names: platform::identify platform::patterns
ex: package require platform => 1.0.19
ex: lindex [platform::patterns [platform::identify]] end => tcl

== msgcat
syn: msgcat::mc src ?arg ...?
does: Message catalogs for text in more than one language, as the msgcat package 1.6.1 of Tcl. Each namespace is a package with its own messages and options. `mcset` adds a translation for a locale, `mclocale` sets the locale, and `mc` gives the text for the current locale and the namespace of the caller or one of its parents, with `format` on the arguments, or calls `mcunknown`. `mcload` sources the `.msg` file of each loaded locale of a folder, `mcpreferences` gives the locale and its parents, `mcexists` tests for a translation, and `mcmax` gives the longest translation. `mcpackagelocale` gives a namespace its own locale, `mcpackageconfig` sets its folder and its callbacks, `mcloadedlocales` lists or clears the loaded locales, and `mcforgetpackage` removes the data of a namespace.
cap: clock
flags: --allow clock
names: msgcat::mc msgcat::mclocale msgcat::mcmset msgcat::mcset msgcat::mcexists msgcat::mcload msgcat::mcmax msgcat::mcpreferences msgcat::mcflset msgcat::mcflmset msgcat::mcunknown msgcat::mcloadedlocales msgcat::mcpackagelocale msgcat::mcpackageconfig msgcat::mcforgetpackage
ex: msgcat::mclocale fr; msgcat::mcset fr Hello Bonjour; msgcat::mc Hello => Bonjour

== exec
syn: exec ?-option ...? arg ?arg ...?
does: Runs a program and gives its output. `|` makes a pipeline, `<` and `>` redirect, and `&` runs it in the background. A process of `exec` is outside the root folder and each limit, with the full power of the user. Turn it on only for scripts that you trust.
cap: exec

== pid
syn: pid ?fileId?
does: The process id of the program, or of the processes of a pipeline.
cap: exec

== exit
syn: exit ?returnCode?
does: Ends the program with the code (0 by default). In an embedded interpreter, the host gets the code.
